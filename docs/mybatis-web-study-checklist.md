## 五、MyBatis 缓存

| 进度 | 编号 | 网页内容 | 要求 | 掌握到什么程度 |
| --- | --- | --- | --- | --- |
| ☐ | 20 | MyBatis 一级缓存是什么？ | 必须掌握 | 掌握默认的 SqlSession 范围、相同查询的命中条件，以及增删改、事务操作、关闭 Session、手动清理等对缓存的影响。 |
| ☐ | 21 | Spring 项目中为什么感觉一级缓存没有生效？ | 必须掌握 | 理解事务边界与 Session 复用；同一事务、同一 SqlSessionFactory 的调用通常复用 Session，无事务时连续调用可能使用不同 Session。 |
| ☐ | 22 | MyBatis 二级缓存是什么？如何开启？ | 必须掌握 | 掌握 namespace 范围、基本开启方式、提交可见和更新失效；知道全局 cacheEnabled 开启不代表每个 namespace 都启用了二级缓存。 |
| ☐ | 23 | 为什么生产项目要谨慎使用 MyBatis 二级缓存？ | 必须掌握 | 能解释跨 Mapper、其他应用更新数据以及多个应用实例等情况下的旧数据与一致性问题。 |
| ☐ | 24 | 一级缓存可能造成脏读吗？ | 必须掌握 | 能区分缓存返回旧数据与数据库事务中“读取其他事务未提交数据”的脏读；知道清缓存也不保证一定读到其他事务的新值。 |

本章验证：先保持二级缓存未启用，在默认一级缓存配置下观察 SQL 日志。事务方法需要通过 Spring 代理调用。

| 验证场景 | 需要解释的现象 |
| --- | --- |
| 同一事务中连续两次完全相同的查询 | 第二次是否命中一级缓存，是否再次执行 SQL |
| 同一事务中查询 → 更新 → 相同查询 | 更新对一级缓存的影响，最后一次查询是否重新访问数据库 |
| 无事务时连续两次相同 Mapper 查询 | 是否使用不同 Session，是否分别执行 SQL |

二级缓存第一轮先掌握范围、开启条件和失效局限，复杂配置与源码可以后补。
