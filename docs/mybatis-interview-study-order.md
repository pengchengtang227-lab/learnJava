# MyBatis 初级面试学习顺序与重点

适用情况：已经学习 Spring Boot，准备学习 MyBatis，每天可投入约 6 小时，目标是 Java 初级业务开发岗位。

学习目标：能独立完成数据库访问代码，讲清常见原理，并通过 SQL 日志排查基本问题。

参考文章：[JavaGuide：MyBatis 常见面试题总结](https://javaguide.cn/system-design/framework/mybatis/mybatis-interview.html)。文章偏重面试总结，下面按“先开发、再理解原理”的顺序重新整理，并补充配套练习。

## 一、学习目标与重点等级

| 标记 | 含义 | 学习要求 |
| --- | --- | --- |
| ★★★ 重点必会 | 日常开发与初级面试的核心内容 | 能自己写、能运行验证、能解释为什么这样写 |
| ★★☆ 原理重点 | 初级面试需要准备的原理与排错知识 | 能用自己的话解释，能结合项目举例，并完成指定验证 |
| ★☆☆ 后续进阶 | 更深入的源码、扩展与特殊场景 | 第一轮认识用途即可，后续按需要深入 |

★★☆ 内容也需要在面试前掌握，主要要求是理解和验证。每阶段的“补充了解”及第五节进阶内容可以后补。

## 二、学习顺序与前置检查

按 1 → 8 学习。先用一个小模块贯穿各阶段，再回头复习文章中的面试问题。

| 顺序 | 学习主题 | 重点等级 | 阶段成果 |
| --- | --- | --- | --- |
| 1 | 基础概念、整合 Spring Boot、基础 CRUD | ★★★ | 跑通一次从接口到数据库的完整调用 |
| 2 | 结果映射与单条查询规则 | ★★★ | 正确处理字段映射、空结果和多条结果 |
| 3 | 参数传递与动态 SQL | ★★★ | 完成多条件查询、动态更新、集合查询 |
| 4 | 主键回填与分页 | ★★★ | 新增后拿到 ID，完成条件分页查询 |
| 5 | Spring 事务与多表写入 | ★★★ | 验证两次写入一起提交、失败一起回滚 |
| 6 | Mapper 代理、执行流程与核心组件 | ★★☆ | 能讲清接口方法如何变成数据库查询 |
| 7 | 线程安全与一级、二级缓存 | ★★☆ | 能解释缓存范围、失效与 Spring 中的表现 |
| 8 | 关联查询、N+1 与排查巩固 | ★★☆ | 能完成简单关联映射，用 SQL 日志解释查询次数 |

前五阶段以动手开发为主，建议投入约 60% 的学习时间；第六至八阶段通过已有功能理解原理。

| 前置知识 | 需要具备的基础 | 不熟悉时怎么补 |
| --- | --- | --- |
| 基础 SQL | 能写简单增删改查、条件过滤和排序 | 开始 MyBatis 前先练习，确保 SQL 在数据库中能运行 |
| JDBC | 知道连接、PreparedStatement、参数绑定和 ResultSet 的用途 | 先理解一次查询的步骤，帮助理解 MyBatis 封装了什么 |
| MySQL 事务 | 知道提交和回滚的含义 | 学第五阶段时结合多表写入练习 |
| 分页与关联 SQL | 理解 LIMIT 和基本 JOIN | 分别在第四、八阶段同步补齐 |

## 三、每天 6 小时：7～10 天第一轮安排

7～10 天是完成第一轮学习和练习的参考时间，约 42～60 小时。实际进度以阶段验收为准；SQL 或 JDBC 基础薄弱时，先补基础并相应延长时间。

| 时间 | 学习内容 | 当天交付 |
| --- | --- | --- |
| 第 1 天 | 第 1 阶段：整合、基础 CRUD、查看 SQL 日志 | 跑通接口到数据库的调用，能找到执行 SQL 和参数 |
| 第 2 天 | 第 2 阶段；第 3 阶段的参数传递部分 | 正确映射字段，完成对象参数与多个参数查询 |
| 第 3 天 | 第 3 阶段的动态 SQL；第 4 阶段 | 完成条件分页、动态更新、集合查询和主键回填 |
| 第 4 天 | 第 5 阶段；回顾前五阶段 | 完成订单与明细写入，并实际验证事务回滚 |
| 第 5 天 | 第 6 阶段；第 7 阶段的基本概念 | 讲清 Mapper 代理、执行链和缓存范围 |
| 第 6 天 | 第 7 阶段的缓存验证；第 8 阶段 | 对照日志解释查询次数，完成简单关联映射和排错 |
| 第 7 天 | 综合练习与自测 | 脱离教程完成核心功能，记录回答不清楚的问题 |
| 第 8～10 天 | 按实际情况补缺和复习 | 重新验证薄弱功能，完成最终自测 |

每天建议分配：**2 小时学习 + 3 小时编码与日志验证 + 1 小时复盘**。复盘记录“今天完成了什么、遇到什么问题、如何定位解决、仍有哪些疑问”，每个阶段通过验收后再勾选清单。

贯穿全程的习惯：从第一天开始，使用开发环境的 MyBatis 日志检查执行 SQL、实际参数和查询次数；将查询结果或更新行数与预期对照。遇到问题先核对 SQL 和参数，再检查 Mapper 与结果映射。

## 四、各阶段学习清单

### 第 1 阶段：基础概念与 Spring Boot 整合 ★★★

对应文章：MyBatis 是什么、Mapper XML 常用元素、不同 Mapper XML 中的 id 是否可以重复。

- [ ] 知道 MyBatis 是持久层框架，底层通过 JDBC 操作数据库，SQL 通常由开发者编写。
- [ ] 理解“半自动 ORM”的含义：通常仍需自己写 SQL，并将参数和查询结果与 Java 对象映射。
- [ ] 能配置数据源、Mapper 扫描和 XML 路径，理解 `@Mapper`、`@MapperScan` 的用途。
- [ ] 理解 XML 的 `namespace` 对应 Mapper 接口全限定名，语句 `id` 对应接口方法名。
- [ ] 会使用 `select`、`insert`、`update`、`delete`；单个值参数先使用 `#{id}` 等方式绑定。
- [ ] 知道不同 namespace 可以有相同 id，同一 namespace 内不能重复定义相同 id。
- [ ] 能在日志中找到执行 SQL、绑定参数，并对照数据库检查结果。

**练习与验收：**完成用户的新增、按 ID 查询、修改和删除；修改、删除使用明确的 ID 条件，检查影响行数。能说明下面每一层的职责，并指出对应的 SQL 日志。

`HTTP 请求 → Controller → Service → Mapper → MySQL → 返回结果`

**补充了解：**MyBatis 与 JPA/Hibernate 在 SQL 控制方式上的基本区别；`sql`、`include` 的 SQL 片段复用方式。

### 第 2 阶段：结果映射与单条查询规则 ★★★

对应文章：`resultType` 与 `resultMap`、查询结果为空或映射不完整、`selectOne()` 查询到多条记录。

- [ ] 理解 `resultType` 适合简单自动映射，`resultMap` 可以明确配置列与属性的关系。
- [ ] 会使用 SQL 列别名、`mapUnderscoreToCamelCase` 和 `resultMap` 处理命名差异。
- [ ] 知道 `resultType` 返回集合时填写的是元素类型。
- [ ] 理解 `selectOne()`：零条返回 `null`，一条返回对象，多条抛出 `TooManyResultsException`。
- [ ] 能检查 SQL 参数、列名、Java 属性名和映射配置，定位结果不正确的问题。

**练习与验收：**将数据库字段 `user_name` 映射到 Java 属性 `userName`；通过返回单个对象的 Mapper 查询方法，分别验证零条、一条、多条结果时的行为。业务要求唯一的数据应由唯一约束保证。

### 第 3 阶段：参数传递与动态 SQL ★★★

对应文章：`#{}` 与 `${}`、多个参数如何引用、动态 SQL 标签、避免 SQL 注入。

- [ ] 会传递单个值、多个参数、对象和集合；多个参数优先使用 `@Param` 明确名称。
- [ ] 理解 `#{}` 生成 JDBC 参数占位符并绑定值，`${}` 直接拼接 SQL 文本。
- [ ] 知道动态表名、列名、排序方向不能用普通值参数代替；需要通过服务端白名单或固定 SQL 分支选择。
- [ ] 熟练使用 `if`、`where`、`set`、`foreach`，知道它们分别处理什么问题。
- [ ] 会处理空集合、没有更新字段和缺少更新 ID 的情况，防止非法 SQL 或意外扩大更新范围。

**练习与验收：**实现姓名和状态均可选的条件查询、按 ID 集合批量查询、只修改指定字段的更新。对照日志验证条件都不传、只传一个条件、同时传两个条件的情况；本练习约定空 ID 集合返回空结果，不执行无条件查询；没有更新字段或缺少 ID 时拒绝更新。

**补充了解：**`choose/when/otherwise`、`trim`、`bind` 的用途；需要时再练习具体写法。

### 第 4 阶段：主键回填与分页 ★★★

对应文章：批量插入与主键回填、`useGeneratedKeys` 和 `selectKey`、分页与分页插件。

- [ ] 会用 `useGeneratedKeys`、`keyProperty` 回填数据库自增主键。
- [ ] 理解插入方法返回的影响行数与回填到对象中的主键是两个概念。
- [ ] 会使用 `LIMIT` 或 PageHelper 等分页插件，返回列表和总条数。
- [ ] 知道 `RowBounds` 默认不会自动把 SQL 改写成带 `LIMIT` 的数据库物理分页。
- [ ] 知道分页应有明确、稳定的排序，深度分页可能带来性能问题。

**练习与验收：**新增用户后能取得生成的 ID；先用 `LIMIT` 完成按条件分页查询，检查第一页、后续页和无结果时的返回，并确认列表与总数使用相同过滤条件。选择分页插件时，理解它可以改写分页 SQL 即可。

**补充了解：**`selectKey` 在插入前或插入后查询主键的用途、分页插件的详细拦截流程、批量主键回填的驱动兼容性。

### 第 5 阶段：Spring 事务与多表写入 ★★★

对应文章：MyBatis-Spring 事务、Mapper 调用成功但数据没有提交。

- [ ] 会在 Service 层使用 `@Transactional`，按业务需要把多次数据库操作放进同一个事务。
- [ ] 知道 Spring 常规默认回滚规则是运行时异常和 `Error` 触发回滚；受检异常需要结合 `rollbackFor` 等规则配置。
- [ ] 理解同类自调用可能绕过 Spring 事务代理，捕获异常后不再抛出可能影响回滚判断。
- [ ] 知道事务管理器和 MyBatis 应使用匹配的数据源。
- [ ] 知道 Spring 管理的 SqlSession 不应手动提交、回滚或关闭；异步线程不会自动继承原线程事务。

**练习与验收：**通过 Controller 调用 Spring 管理的 Service，在事务方法中同时写入订单表和明细表。先验证成功提交，再让第二次写入失败并抛出符合回滚规则的异常，检查两张表的数据是否回滚；排查时结合事务日志和实际数据库结果。

**学完前五阶段的检查：**脱离教程完成条件分页、新增主键回填和两张表事务回滚。做到这一步，可以开始学习 Redis，同时继续完成下面的面试原理与排错内容。

### 第 6 阶段：Mapper 代理与执行流程 ★★☆

对应文章：核心组件、Mapper 接口原理、方法重载、完整查询流程。

- [ ] 知道 Mapper 接口由 MyBatis 通过 JDK 动态代理生成代理对象。
- [ ] 知道映射语句通常按“接口全限定名 + 方法名”定位，不按方法参数签名区分 SQL，因此应避免用重载映射不同 SQL。
- [ ] 认识 `SqlSessionFactory`、`SqlSession`、`MappedStatement`、`Executor` 的基本职责。
- [ ] 知道 SQL 执行包含生成 SQL、绑定参数、JDBC 执行、结果映射等步骤。
- [ ] 知道启动时会解析配置和 Mapper 映射，运行时再根据实际参数执行。

**面试表达参考（简化链路）：**

`Mapper 代理 → SqlSession → Executor → JDBC 执行 → 结果映射 → 返回对象`

**验收标准：**能用自己的话讲清“Mapper 接口没有实现类为什么可以调用”，并说明 MyBatis 会将参数绑定到 JDBC 语句、将 ResultSet 映射为 Java 对象。

**补充了解：**认识 `ParameterHandler`、`ResultSetHandler` 对应参数处理和结果映射；内部类的完整调用栈及源码解析可后补。

### 第 7 阶段：线程安全与缓存 ★★☆

对应文章：组件线程安全、一级缓存、Spring 中一级缓存未生效、二级缓存、缓存旧数据及二级缓存局限。

| 知识点 | 必须理解的结论 |
| --- | --- |
| 线程安全 | `SqlSessionFactory` 通常共享使用；原生 `SqlSession` 不能跨线程共享；Spring 注入的 Mapper 由线程安全的 `SqlSessionTemplate` 支持 |
| 一级缓存 | 默认以 SqlSession 为范围；缓存键包含映射语句、最终 SQL、参数等信息，相同查询才可能命中 |
| 一级缓存失效 | 增删改、提交、回滚、关闭 Session、手动清理等操作会影响或清空缓存 |
| Spring 中的表现 | 同一 Spring 事务、同一 SqlSessionFactory 的调用通常复用绑定的 Session；没有事务时，连续两次 Mapper 调用可能使用不同 Session |
| 二级缓存 | 以 namespace 为范围，可以跨 Session 共享；全局 `cacheEnabled` 默认开启，但具体命名空间仍需配置 `cache` 等才能使用 |
| 二级缓存可见与失效 | 查询结果通常在事务提交后对其他 Session 的二级缓存可见；当前 namespace 的增删改默认会清空相应缓存 |
| 二级缓存局限 | 跨 Mapper、其他应用修改数据、本地多实例等场景可能导致缓存旧数据；它不会自动解决跨应用一致性 |
| 缓存与隔离级别 | 缓存返回旧对象不等于数据库隔离级别意义上的“脏读”；清缓存也不保证能看到其他事务的新值 |

**练习与验收：**先保持二级缓存未启用，在默认一级缓存配置下，对照下面三种情况的 SQL 日志。事务方法需通过 Spring 代理调用。

| 验证场景 | 观察重点 |
| --- | --- |
| 同一事务中连续两次完全相同的查询 | 第二次是否命中一级缓存，是否再次访问数据库 |
| 同一事务中查询 → 更新 → 相同查询 | 更新是否清理一级缓存，最后一次查询是否重新访问数据库 |
| 无事务时连续两次相同 Mapper 查询 | 两次调用是否使用不同 Session，是否各自访问数据库 |

能解释观察到的现象，即达到本阶段主要目标。二级缓存先掌握范围、开启方式、提交可见和失效局限；复杂配置可后补。这部分可以在学习 Redis 前完成。

### 第 8 阶段：关联查询、N+1 与排查巩固 ★★☆

对应文章：`association` 与 `collection`、N+1、延迟加载、结果排查、SQL 性能排查、常见误区。

- [ ] 知道 `association` 映射单个关联对象，`collection` 映射关联对象集合。
- [ ] 能完成简单关联映射；Join 查询注意重名列别名，主对象和子对象正确配置标识映射。
- [ ] 能解释 N+1：查出 N 条主记录后，再逐条查询关联数据，共产生约 1 + N 次查询。
- [ ] 知道可以通过适当 Join 或分批查询后组装对象减少 N+1；同时避免过度 Join 导致结果集膨胀。
- [ ] 理解延迟加载是在访问相关属性时再查询，可能带来额外 SQL；代理库细节可后补。
- [ ] 遇到查询慢时，先获取 SQL 与参数、检查查询次数和数据量，再结合 MySQL 的 `EXPLAIN` 查看执行计划。

**练习与验收：**完成“订单关联用户”和“订单关联多条明细”的简单查询；通过日志统计 SQL 次数。故意制造一次字段映射错误，按 SQL、参数、列名、属性和映射配置的顺序排查。

**补充了解：**深层嵌套映射、连接池等待分析、结果传输和对象映射耗时。SQL 索引与执行计划的深入分析，可在 MySQL 专题中继续学习。

## 六、最终自测与进入 Redis 的标准

面试前，用自己的话回答下面的问题，并结合已完成的项目举例。

| 自测问题 | 回答或实践应覆盖的关键词 |
| --- | --- |
| Mapper 接口为什么不用自己写实现类？ | JDK 动态代理、接口名与方法名、映射语句 |
| 字段名和属性名不一致怎么办？ | 列别名、驼峰映射、`resultMap` |
| 单条查询查出多条数据会怎样？ | `TooManyResultsException`、业务唯一约束 |
| 多个参数和集合怎样传入 XML？ | `@Param`、参数名称、`foreach` |
| `#{}` 和 `${}` 怎么选？ | 参数绑定、文本拼接、注入风险、动态标识符白名单 |
| 可选条件和动态更新怎样写？ | `if`、`where`、`set`、空集合、更新字段和 ID 检查 |
| 新增后怎样获取自增 ID？ | `useGeneratedKeys`、`keyProperty`、回填对象属性 |
| 分页有哪些方式？ | SQL 物理分页、分页插件、RowBounds、稳定排序 |
| 两次写入如何保证一起成功或回滚？ | Service 事务、异常回滚规则、Spring 代理 |
| 为什么连续查询两次仍然执行两次 SQL？ | 真实 Session、事务边界、查询参数、缓存失效 |
| 一级缓存与二级缓存有什么区别？ | SqlSession、namespace、开启方式、失效和一致性局限 |
